# Chapter 2: 讨论关键结果，复盘 OKR 实施过程中的问题

> **何时读**：共创 KR、砍非 P1、处理坏消息与人岗问题。评审「独撰下发」的 OKR 时先看本章。

## Core Idea
OKR 不是创始人独角戏写完下发；必须和团队讨论关键结果、砍掉无关业务、正视坏消息，并用优先级与截止日期把聚焦落到日常。

## Frameworks Introduced
- **团队共创 OKR**：真正的 OKR 是大家一起定目标、一起找 KR——「这是我们的公司」。
  - When to use: 第二季及以后；或第一季下发后执行冷淡时。
  - How: 公开使命与约束 → 共拟 O → 共拟 KR → 排优先级 → 明确谁负责什么。
- **砍掉与关键结果无关的业务**：资源有限时，非 P1 的工作（含「看起来漂亮」的设计/项目）要敢于停。
  - When to use: 周中任务膨胀、人人很忙但 KR 不动时。
  - How: 每项工作问「这推进哪条 KR？」推不动则降级或砍掉。
- **直面坏消息与责任到人**：隐瞒进度比失败更伤聚焦。
  - When to use: 指标下滑、人员不匹配、质量事故时。
  - How: 周一谈事实与阻碍；人事问题及时处理；质量与截止时间写入讨论。
- **「一次说太多 = 什么都没说」**：沟通目标要少而反复，而不是清单轰炸。
  - When to use: 全员会、周报、战略同步。
  - How: 只强调当前 OKR；重复到「你不想再说时，人们才开始听进去」（后文章引用韦纳）。

## Key Concepts
- **关键结果讨论会**：把抽象 O 落成可检视的 KR。
- **害群之马 / 人岗匹配**：执行文化的一部分，服务于聚焦而非情绪。
- **截止日期**：制造必要张力，服务重要不紧急事项。
- **产品质量**：可作为 KR 维度，防止只追增长。
- **削减开支时机**：在破产前主动做，而非崩溃后。

## Mental Models
- Use **共创** when 上季「给你的 OKR」导致被动执行。
- Prefer **少说、反复说** over 长篇战略 PPT。
- Treat **砍业务** as 聚焦的证明，不是残忍。

## Anti-patterns
- **创始人独撰 OKR 后甩锅团队**。
- **保留所有历史项目「以防万一」**。
- **回避坏消息直到季末惊吓**。
- **会议上信息过载**，无人记得真正的 KR。

## Worked Example
第二季 TeaBee：汉娜不再「把写好的 OKR 发给大家」，而是用「要不要换掉这张不稳的会议桌」类比——一起装好的桌子才有意义 → 一起定目标。  
同时杰克因设计工作非 P1 而调整人员配置，把精力拉回营收相关 KR——说明「聚焦」包含艰难取舍。

## Key Takeaways
1. 共创提高认同与质量。
2. 每项工作映射到 KR，否则砍或降级。
3. 坏消息早暴露；责任到人。
4. 沟通要短、准、重复。
5. 质量、成本、人岗都是聚焦的一部分。
