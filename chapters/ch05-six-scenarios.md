# Chapter 5: OKR 使用的六大场景

> **何时读**：季度会 / 7 步级联 / 部门教练 / MVP 卡 / 周报 / 避坑体检。可粘贴稿 → [examples.md](../examples.md)；速查 → [cheatsheet.md](../cheatsheet.md)。

## Core Idea
把 OKR 从概念变成可复制的会议与文档：季度设定会、部门关联教练、七步展开、MVP 看板卡、OKR 周报，以及一张「常见坑」清单。

## Frameworks Introduced

### 场景1：季度 OKR 会议
- 人数宜少（十余人级）；禁手机电脑；会前向全员征集目标（窗口短，如一天）。
- 约 4.5 小时（两段×2h + 30min 休）；熟练后可压成一段。
- 高管各带 1–2 个目标 + 员工热门建议 → 便利贴上墙 → 去重合并 → **投票减到约 3 个** → 再自由列举指标 → 分组 → 先定「测什么」再定「X 是多少」 → 校准 50% 信心 → 5 分钟终检（鼓舞？有意义？够难？能扛一季？）。
- 经验：每目标尽量覆盖用户/收入/满意度等不同类型 KR，防失衡。

### 场景2：服务部门与公司目标关联
用教练提问把「我们帮销售」变成可衡量结果：消歧义、对齐定义、要历史基线、关注结果非任务、改写为积极指标（如**技术合格率**）。  
与其 CEO 强塞，不如经理共商。

### 场景3：OKR 会议 7 步
1. 全员提交候选公司目标  
2. 管理层半天选定 O + KR  
3. 部门会（自由列举→分组→投票）产出部门 OKR  
4. CEO 校验偏差（必要时再开 1h）  
5. 子部门自上而下关联  
6. 个人 OKR（可选，一对一确认）  
7. 全员会：解释为什么、示范拆解、回顾上季、立刻行动  

两周内定不完 → 调其他优先级；设 OKR 难，勿当戏法。  
**第一次**：全公司仅一个 OKR；或试点独立团队；或先用项目级 OKR。

### 场景4：MVP / 看板卡上的 OKR（GatherContent）
上卡前必须答：我们想达成什么？如何衡量成败？  
可将「目标」语义改为「假设」以鼓励证伪。用 OKR 排优先级、对齐业务、减少情绪争执；设衡量截止日并复盘学习。

### 场景5：OKR 周报结构
1. 团队 OKR + 信心指数（≤3 红，≥7 绿）  
2. 上周优先事项及完成情况（未完成简述阻碍）  
3. 下周优先事项（约 3 件，要完整可交付，忌「和律师聊聊」）  
4. 风险/阻碍（求协同，不甩锅）  
5. 备注（好人好事、团建等）  

周报发给需要协同的管理层；工作是共同目标而非杂事列表。

### 场景6：常见坑
- 多个目标记不住（多业务线才多 OKR）  
- 周期过短（一周/一月；一周能做完的是任务）  
- 用绩效数字当「鼓舞目标」  
- 无信心指数 / 不追踪指数变化  
- 周一会变成汇报而非谈话  
- （失败定义含：全没完成、全完成却无正面影响、实施了但公司无改进）

## Key Concepts
- **自由列举 / 归类分组 / 投票排序**
- **技术合格率** 等积极结果指标
- **假设型 MVP OKR**
- **红/绿信心标记**

## Mental Models
- Prefer **先收敛目标再填数值**。
- Use **教练问题** when 职能部门说「我们很重要但不可测」。
- Prefer **小范围首次实践** over 全公司一次铺开后幻灭。

## Anti-patterns
- 季度会无准备、回避做决定。
- KR 两项都是收入导致短期赌博。
- 个人 OKR 只靠邮件下达。
- 周报变「证明我很忙」的流水账。

## Worked Example
研发「帮销售」→ 教练追问后变为：主要潜客（年收入>$100k）的**技术合格率**基线与目标，并与销售 VP 对齐定义——从活动计数变成业务结果。

## Key Takeaways
1. 季度会是设计过的决策过程，不是聊天。
2. 部门 OKR 必须可验证地贡献公司 O。
3. 七步级联 + 两周死线。
4. MVP/周报是日常载体。
5. 对照坑清单做季前体检。
